100 万 Token 可能只有极少部分真正创造了价值。与其让 AI 不断生成 HTML、CSS、React，不如让它只生产 JSON、YAML 和 DSL，再交给编译器生成完整软件。

**文章核心观点**

- AI 不应该承担大量重复性的代码生成。
- div、class、CRUD、表单等应该由编译器和模板引擎完成。
- AI 应该负责业务理解、结构设计和规则表达。
- 软件生产应该从 Code Generation 转向 Specification Generation。

## 文章结构建议

我建议写成一篇有技术深度、有个人观点、有未来判断的文章，而不是单纯介绍 JSON/YAML。

1\. **一个荒谬的现象：100 万 Token，真正有价值的内容有多少？**

- AI 生成大量重复代码。
- HTML、CSS、类型定义、CRUD、组件反复出现。
- Token 消耗和实际业务价值严重不匹配。

2\. **我们是不是用错了 AI？**

- AI 擅长理解需求、推理和抽象。
- 却让它重复生产确定性的代码。
- 编译器早就能做的事情，为什么还要让 AI 做？

3\. **换一种思路：AI 只生产 JSON/YAML**

- 结构化规格。
- DSL。
- AST / IR。
- 编译器生成完整程序。

4\. **真正的软件生产流水线**

- AI Specification。
- Schema Validation。
- Semantic Analysis。
- AST Compiler。
- Code Generation。
- Build &amp; Test。

5\. **这会不会是 AI Coding 的下一次范式转移？**

- Token 成本下降。
- 代码一致性提高。
- 可预测构建。
- 增量编译。
- 错误局部修复。

6\. **最后一个问题：未来程序员究竟是在写代码，还是在设计软件？**

**我的建议：选第一个标题。**

它有冲突、有立场，也有足够大的讨论空间。文章不要把观点写成「AI 永远不应该写代码」，而应该提出一个更有价值的命题：

**当代码已经可以被确定性地生成，我们为什么还要浪费昂贵的智能去重复生产代码？**
